## 1. 요구사항과 명세서가 안 맞는 부분

| 요구사항 | 요구사항 내용 | 명세서 내용 | 정해야 할 것 |
| --- | --- | --- | --- |
| REQ-BOARD-009 | 게시글 작성 시 **첨부파일 업로드 버튼** | 게시글은 URL 링크(`links`)만 받음. 첨부파일은 질문·답변·신고용만 있음 | 게시글에도 첨부파일을 허용할지 **(보류: 모든 글쓰기에 WYSIWYG 에디터를 도입할 때 함께 결정)** |

## 2. 필드 길이: 정해지지 않은 규칙

이미 정해진 길이는 다음과 같습니다.

| 대상 | 정해진 길이 |
| --- | --- |
| 회원 | `name` 1~16, `username` 4~20, `nickname` 2~16, `email` 128, `password` 8~32 (Argon2id 해시), `bio` 0~200 ([API 명세 1.8](../backend/docs/API_SPEC.md#18-회원-입력값-규칙)) |
| 질문 | `title` 1~100 |
| 답변 | `body` 1~5000 |
| 게시글·댓글 | 게시글 `title` 1~80, 댓글 `body` 1~500 |
| 태그 | 이름 1~30, 설명 100 |
| 신고 | `detail` 1000 |
| 공지 | `title` 1~100 |
| 관리자 | 사유 200 |
| 첨부파일 | 원본 파일명 15자 (넘으면 확장자 유지하고 줄임), 질문·답변·신고 1건당 최대 3개, URL 저장 |

아래는 아직 정해지지 않았습니다.

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| `questions.body` | 공백 제외 15자 이상 | **최대 길이** |
| `posts.body` | 1자 이상 | **최대 길이** |
| `posts.links` | 최대 5개, `http(s)` | URL 1개의 최대 길이, 저장 방식(별도 테이블 또는 JSON) |
| `notices.body` | 필수만 | 최대 길이 |
| `attachments.url`, `profileImageUrl` | URL을 그대로 저장하기로 확정 | URL 컬럼 최대 길이 |
| `editReason` | 최대 200자 | 화면에는 `isEdited`만 쓰는데, 수정 사유를 어디에 저장할지(수정 이력 테이블을 둘지) |
| `activity_logs` | 없음 | `detail`, `targetLabel` 길이 |

## 3. 중복 불가: 정해지지 않은 규칙

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| `username`, `email`, `nickname` | 중복 불가, 대소문자 무시 비교 | 탈퇴한 회원의 값을 다시 쓸 수 있는지. 탈퇴 회원 행을 남기면 중복 검사와 충돌함. DB 정렬 규칙(collation)으로 대소문자를 무시할지, 소문자로 바꿔 저장할지 |
| 답변 채택 | 질문당 1개 | 저장 위치: 질문 쪽에 채택 답변 id를 둘지, 답변 쪽에 채택 여부를 두고 제약을 걸지 |
| 신고 | 같은 회원·같은 대상은 처리 대기 중에만 중복 불가 | 처리가 끝난 뒤에는 다시 신고할 수 있어 일반 unique 제약으로는 안 됨. 앱에서 검사할지, DB 설계로 막을지 |
| 조회수 | 같은 회원 또는 IP는 24시간에 1회 | 조회 기록 저장소(DB 테이블 또는 메모리·Redis) |

## 4. 삭제 정책: 정해지지 않은 규칙

모든 삭제는 soft delete(`status` 변경)로 확정했습니다. ([API 명세 1.7](../backend/docs/API_SPEC.md#17-삭제-정책-soft-delete)) 남은 것은 아래와 같습니다.

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| 회원 탈퇴 | 행을 남기고 `status: withdrawn` | 남긴 행의 개인정보(이름·이메일·비밀번호)를 비식별 처리할지. 같은 아이디·이메일·닉네임으로 재가입을 허용할지([3장](#3-중복-불가-정해지지-않은-규칙)과 연결) |
| 첨부파일 | 행을 남기고 `status: deleted` | 저장소의 실제 파일도 남길지 |
| 활동 로그·정지 이력 | 기록만 정의 | 보관 기간. 관리자가 탈퇴했을 때 처리 |

---

## 5. 제안하는 기본 방향

결정 전 논의용 제안입니다.

- 탈퇴 회원은 개인정보를 비식별 처리한 행을 남깁니다. 그러면 작성글은 "탈퇴한 회원"으로 연결이 유지되고, 그 행의 아이디·이메일·닉네임을 비워 두면 같은 값으로 다시 가입할 수 있습니다.
