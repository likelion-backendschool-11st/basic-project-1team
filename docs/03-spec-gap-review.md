## 1. 요구사항과 명세서가 안 맞는 부분

| 요구사항 | 요구사항 내용 | 명세서 내용 | 정해야 할 것 |
| --- | --- | --- | --- |
| REQ-BOARD-009 | 게시글 작성 시 **첨부파일 업로드 버튼** | 게시글은 URL 링크(`links`)만 받음. 첨부파일은 질문·답변·신고용만 있음 | 게시글에도 첨부파일을 허용할지 **(보류: 모든 글쓰기에 WYSIWYG 에디터를 도입할 때 함께 결정)** |

## 2. 필드 길이: 확정된 규칙


| 대상 | 정해진 길이 |
| --- | --- |
| 회원 | `name` 1~16, `username` 4~20, `nickname` 2~16, `email` 128, `password` 8~32 (Argon2id 해시), `bio` 0~200 ([API 명세 1.8](../backend/docs/API_SPEC.md#18-회원-입력값-규칙)) |
| 질문 | `title` 1~100 |
| 질문·답변·게시글·공지 본문 | 글자 최대 10,000자, 저장 문자열 최대 100,000자, `MEDIUMTEXT` ([API 명세 1.9](../backend/docs/API_SPEC.md#19-본문--url-규칙)) |
| URL | 첨부·프로필 `VARCHAR(512)`, 게시글 링크 `VARCHAR(2048)` (`post_links` 테이블) |
| 게시글·댓글 | 게시글 `title` 1~80, 댓글 `body` 1~500 |
| 태그 | 이름 1~30, 설명 100 |
| 신고 | `detail` 1000 |
| 공지 | `title` 1~100 |
| 관리자 | 사유 200 |
| 활동 로그 | `detail` 256, `targetLabel` 16 (`<종류> #<id>` 형식) |
| 첨부파일 | 원본 파일명 15자 (넘으면 확장자 유지하고 줄임), 질문·답변·신고 1건당 최대 3개, URL 저장 |

필드 길이는 모두 정했습니다.

## 3. 중복 불가: 확정된 규칙

모두 확정해 [API 명세 1.10](../backend/docs/API_SPEC.md#110-대소문자--중복-검사--저장-방식)에 반영했습니다.

| 대상 | 확정 |
| --- | --- |
| 대소문자 | 아이디·이메일·닉네임 비교, 로그인, 검색 모두 **대소문자 구분** (`utf8mb4_bin` 또는 `utf8mb4_0900_as_cs`). 태그만 이름 규칙대로 소문자 정규화 후 비교 |
| `username`, `email`, `nickname` | 탈퇴하면 값을 비워(`NULL`) 같은 값으로 재가입 가능 |
| 답변 채택 | 답변 쪽 상태값 `answers.is_accepted`. 질문당 1개는 앱에서 검사 |
| 신고 | 같은 회원·같은 대상의 `pending` 중복은 앱에서 검사 |
| 조회수 | DB 테이블 `view_histories` (대상·조회자별 1행, 마지막 조회 시각 갱신) |

## 4. 삭제 정책: 확정된 규칙

모든 삭제는 soft delete(`status` 변경)입니다. ([API 명세 1.7](../backend/docs/API_SPEC.md#17-삭제-정책-soft-delete))

| 대상 | 확정 |
| --- | --- |
| 회원 탈퇴 | 행은 남기고 개인정보(아이디·이메일·닉네임·이름·비밀번호 해시·프로필 사진·소개글)를 비식별 처리(`NULL`). 프로필 사진 파일은 저장소에서 삭제 |
| 첨부파일 | 행은 `status: deleted`로 남기고, 저장소의 실제 파일은 삭제 |
| 활동 로그 | 보관 기간 5년. 지나면 `status: expired`로 바꾸고 조회에서 제외(행은 남김). 처리한 관리자가 탈퇴하면 "탈퇴한 회원"으로 표시 |
| 정지 이력 | 회원 행과 함께 계속 보관 |
