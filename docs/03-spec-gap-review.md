## 1. 요구사항과 명세서가 안 맞는 부분

| 요구사항 | 요구사항 내용 | 명세서 내용 | 정해야 할 것 |
| --- | --- | --- | --- |
| REQ-ADMIN-004 | 특정 회원에게 게시물 삭제 같은 **권한 부여** | 권한 변경은 이번 범위 제외 | 요구사항에서 뺄지, 명세에 넣을지 |
| REQ-ADMIN-008 | 기본은 숨김, 영구 삭제는 **별도 버튼과 확인 창** | 관리자 삭제 API는 있으나 확인 창 언급 없음. 화면도 질문·게시글 삭제가 확인 없이 바로 실행됨 | 관리자 삭제에 확인 창 추가 |
| REQ-ADMIN-010 | 태그 삭제는 행을 지우지 않고 **`blocked` 상태로 바꿔 같은 태그 재생성 방지** | 사용 중이어도 삭제, 질문과 연결만 끊음. `blocked` 상태 없음 | 삭제 방식 ([4장](#4-삭제-정책-정해지지-않은-규칙)과 같은 문제) |
| REQ-ADMIN-012 | 게시글·**댓글** 숨김·복구·**삭제** | 댓글은 숨김·복구만 있고 관리자 삭제 API 없음 | 관리자 댓글 삭제를 넣을지 |
| REQ-LOGIN-001 | 로그인 후 **질문 게시판**으로 이동 | 보던 화면(`redirect`)으로 복귀, 없으면 질문 목록 | 요구사항을 명세 쪽으로 고칠지 |
| REQ-MYPAGE-002·003 | 질문·게시물 보기를 누르면 **각 게시판으로 이동해 작성자 검색** | 프로필 안의 질문·답변·게시글 탭에서 보여 줌 | 요구사항을 명세 쪽으로 고칠지 |
| REQ-BOARD-009 | 게시글 작성 시 **첨부파일 업로드 버튼** | 게시글은 URL 링크(`links`)만 받음. 첨부파일은 질문·답변·신고용만 있음 | 게시글에도 첨부파일을 허용할지 |
| REQ-QNA-005 | 채택되었거나 **추천을 많이 받은 답변을 맨 위에 고정** | 채택 답변만 맨 위, 나머지는 추천순 또는 최신순 정렬 | "많이 받은" 기준과 고정 방식 |
| REQ-QNA-008·009 | 신고받은 질문·답변은 **임시 비활성** | 신고만으로는 숨기지 않음. 관리자가 처리할 때 숨김 선택 | 신고 즉시 숨길지, 숨긴다면 신고 몇 건부터인지 |
| REQ-QNA-012 | **채택된 답변은 수정·삭제 불가** | 삭제만 불가, **수정은 가능**하다고 명시 | 채택된 답변의 수정 허용 여부 |
| REQ-TAG-002 | 태그 상세정보 출력 | 일반 회원용은 태그 목록 API만 있음. 상세 API와 화면 없음 | 태그 상세 API·화면을 만들지 |
| REQ-TAG-003 | 태그 상세 수정: 관리자 + **계정레벨 n 이상 회원** | 관리자만 가능. 레벨은 이번 범위 제외(D-8) | 회원 수정 권한 제외 여부 |
| REQ-TAG-004 | 태그 동의어 제안·추천 투표 (추천 5 이상 등록, -2 미만 삭제) | 없음. 관리자 병합만 있음 | 범위 제외 여부 |

### 명세서에만 있고 요구사항에는 없는 기능

요구사항에 추가할지 정해야 합니다.

- 답변 추천·추천 취소
- 공지 화면(헤더 롤링, 목록, 상세)과 공지 API
- 공개 프로필과 작성 목록
- 신고 10초 내 취소
- 비회원 읽기와 로그인 안내 팝업
- 조회수 중복 방지

## 2. 필드 길이: 정해지지 않은 규칙

이미 정해진 길이는 다음과 같습니다.

| 대상 | 정해진 길이 |
| --- | --- |
| 회원 | `name` 1~20, `username` 4~20, `nickname` 2~12, `bio` 0~200 |
| 질문 | `title` 1~100 |
| 답변 | `body` 1~5000 |
| 게시글·댓글 | 게시글 `title` 1~80, 댓글 `body` 1~500 |
| 태그 | 이름 1~30, 설명 100 |
| 신고 | `detail` 1000 |
| 공지 | `title` 1~100 |
| 관리자 | 사유 200 |

아래는 아직 정해지지 않았습니다.

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| `users.email` | 이메일 형식만 | 최대 길이 |
| `users.password` | 8자 이상만 | 최대 길이. 저장할 해시 방식과 컬럼 길이. 복잡도 규칙도 다름(비밀번호 변경 화면은 "영문/숫자/특수문자 8자 이상", 로그인 화면은 "Min. 8 characters") |
| `users.nickname`, `users.name` | 길이만 | 공백·특수문자·이모지 허용 여부 |
| `questions.body` | 공백 제외 15자 이상 | **최대 길이** |
| `posts.body` | 1자 이상 | **최대 길이** |
| `posts.links` | 최대 5개, `http(s)` | URL 1개의 최대 길이, 저장 방식(별도 테이블 또는 JSON) |
| `notices.body` | 필수만 | 최대 길이 |
| `attachments` | 형식·용량만 | 원본 파일명 길이, URL 대신 저장 경로를 저장할지. 질문·답변 1개당 첨부 개수 상한(신고만 3개로 정해짐) |
| `profileImageUrl` | 없음 | URL 또는 경로 길이 |
| `editReason` | 최대 200자 | 화면에는 `isEdited`만 쓰는데, 수정 사유를 어디에 저장할지(수정 이력 테이블을 둘지) |
| `activity_logs` | 없음 | `detail`, `targetLabel` 길이 |

## 3. 중복 불가: 정해지지 않은 규칙

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| `username`, `email`, `nickname` | 중복 불가, 대소문자 무시 비교 | 탈퇴한 회원의 값을 다시 쓸 수 있는지. 탈퇴 회원 행을 남기면 중복 검사와 충돌함. DB 정렬 규칙(collation)으로 대소문자를 무시할지, 소문자로 바꿔 저장할지 |
| 태그 이름 | 정규화한 이름 기준 중복 불가 | 삭제되거나 병합된 태그 이름을 다시 만들 수 있는지(REQ-ADMIN-010의 `blocked`와 직결) |
| 답변 채택 | 질문당 1개 | 저장 위치: 질문 쪽에 채택 답변 id를 둘지, 답변 쪽에 채택 여부를 두고 제약을 걸지 |
| 답변 추천 | 이미 추천하면 `409 ALREADY_VOTED` | (답변, 회원) 조합 unique 제약으로 확정할지 |
| 신고 | 같은 회원·같은 대상은 처리 대기 중에만 중복 불가 | 처리가 끝난 뒤에는 다시 신고할 수 있어 일반 unique 제약으로는 안 됨. 앱에서 검사할지, DB 설계로 막을지 |
| 조회수 | 같은 회원 또는 IP는 24시간에 1회 | 조회 기록 저장소(DB 테이블 또는 메모리·Redis) |

## 4. 삭제 정책: 정해지지 않은 규칙

| 대상 | 현재 명세 | 정해야 할 것 |
| --- | --- | --- |
| 회원 탈퇴 | "즉시 삭제(**또는** 개인정보 파기 후 비활성화)", 작성글은 남김 | 둘 중 하나로 확정. 작성글의 작성자 처리(작성자를 비울지, 익명화한 회원 행을 남길지). 추천·신고·정지 이력 처리 |
| 질문 | 답변이 있으면 작성자가 삭제 불가. 관리자 삭제 시 답변도 삭제 | 실제로 지울지(hard), 삭제 표시만 할지(soft). 태그 연결·추천·첨부파일을 함께 지울지 |
| 답변 | 채택 답변은 작성자가 삭제 불가. 관리자가 지우면 채택 해제 | 실제 삭제 또는 삭제 표시, 추천 기록 처리 |
| 게시글 | 댓글도 함께 삭제 | 작성자 삭제를 실제 삭제로 할지 삭제 표시로 할지. 요구사항상 관리자 삭제는 영구 삭제 |
| 댓글 | 작성자 삭제만 있음 | 실제로 지울지, "삭제된 댓글입니다"로 남길지 |
| 태그 | 삭제하고 질문 연결만 끊음 | 요구사항의 `blocked` 상태 방식과 충돌. 하나로 정해야 함 |
| 첨부파일 | 24시간 동안 글에 연결되지 않으면 정리 | 글이 지워질 때 저장소의 실제 파일도 지울지 |
| 신고 | 대상이 삭제되어도 신고는 남김(미리보기는 `null`) | 대상 글에 외래키를 걸 수 없음(대상 종류가 여러 개). 접수 취소 시 행을 지울지, 취소 상태를 둘지 |
| 공지 | 삭제 API만 있음 | 실제 삭제 또는 삭제 표시 |
| 활동 로그·정지 이력 | 기록만 정의 | 보관 기간. 관리자가 탈퇴했을 때 처리 |

## 5. 제안하는 기본 방향

결정 전 논의용 제안입니다.

- 회원, 질문, 답변, 게시글, 댓글은 삭제 시각(`deleted_at`)을 남기는 soft delete로 통일합니다. 관리자 영구 삭제만 실제로 지웁니다.
- 탈퇴 회원은 개인정보를 지운 행을 남깁니다. 그러면 작성글은 "탈퇴한 회원"으로 연결이 유지되고, 그 행의 아이디·이메일·닉네임을 비워 두면 같은 값으로 다시 가입할 수 있습니다.
- 태그는 요구사항대로 `blocked` 상태를 둡니다.
